# Лабораторная работа №28 — шаблон MVP

**Тема:** AMFIBIA — маркетплейс брендовой одежды. Настольная WPF-версия сайта
[Fashion_site](https://github.com/JLeizy/Fashion_site) для покупателя: 15 модных домов, 714 настоящих вещей,
корзина, оформление заказа и личный кабинет. Приложение написано по шаблону **Model — View — Presenter**.

## Как открыть и запустить

1. Открыть **Visual Studio 2026** → «Открыть проект или решение» → `Lab28_MVP.sln`.
   Нужна рабочая нагрузка «Разработка классических приложений .NET» (.NET 10).
2. Нажать **F5**.
3. Войти: **`buyer@amfibia.by`**, пароль **`Amfibia2026`** (или нажать кнопку демо-аккаунта под формой).

| Аккаунт | Что покажет |
|---|---|
| `buyer@amfibia.by` | Покупатель с заказами во всех статусах, может оставлять отзывы |
| `anna.kovaleva@example.com` | Другой покупатель |
| `blocked.user@example.com` | Ошибка «Аккаунт заблокирован» |
| Кнопка «Зарегистрироваться» | Новый аккаунт с проверкой всех полей |

Промокоды: `AMFIBIA10` (−10 %), `GOTHIC15` (−15 %), `WELCOME20` (−20 %). Тестовая карта: `4242 4242 4242 4242`.

Личные данные (регистрации, корзина, избранное, заказы, отзывы, профиль) сохраняются между запусками
в `%AppData%\AMFIBIA\Lab28_MVP`. Чтобы вернуть демо-данные, удалите эту папку.

## Как устроен MVP

```
AmfibiaShop/
├── Models/                МОДЕЛЬ — данные и правила магазина, ничего не знает об окнах
│   ├── ShopData.cs          данные сайта из Data/amfibia.json
│   ├── AuthModel.cs         вход, регистрация, профиль, пароль
│   ├── CatalogModel.cs      поиск, фильтры, сортировки, страницы, подборки
│   ├── CartModel.cs         корзина: количество, промокоды, доставка, суммы
│   ├── OrderModel.cs        оформление, статусы, отмена, возврат, трек-номера
│   ├── ReviewModel.cs       отзывы и правило «только после покупки»
│   ├── WishlistModel.cs, CompareModel.cs, CurrencyModel.cs, Storage.cs, ShopContext.cs
├── Views/                 ВИД — окна и страницы WPF, только показывают и передают события
│   ├── IShellView.cs, Auth/IAuthViews.cs, Pages/IPageViews.cs   интерфейсы видов
│   ├── MainWindow.xaml      шапка и место для страниц
│   ├── Auth/                окно входа: LoginView, RegisterView
│   ├── Pages/               11 страниц: Home, Catalog, Product, Brands, Brand, Wishlist,
│   │                        Compare, Cart, Checkout, Orders, Profile
│   └── Controls/            карточка товара, рисунок товара, преобразователи
├── Presenters/            ПРЕДСТАВИТЕЛЬ — связь Вида и Модели
│   ├── AuthPresenters.cs    LoginPresenter, RegisterPresenter
│   ├── ShellPresenter.cs    навигация, «Назад», счётчики, валюта, выход
│   ├── HomePresenter.cs … ProfilePresenter.cs   по одному на страницу
│   ├── Display/             готовые к показу данные (цены уже отформатированы)
│   └── Validation.cs, Format.cs
├── Themes/Theme.xaml      тёмная тема и шрифты сайта
├── Fonts/                 Cormorant Garamond, Inter, UnifrakturMaguntia (лицензия SIL OFL)
└── App.xaml.cs            сборка: создаёт Модели, Виды и Представителей и связывает их
```

**Правила, которые соблюдаются во всём проекте:**

1. Вид не проверяет данные и ничего не считает — только показывает и сообщает о действиях событиями
   (`LoginRequested`, `AddToCartRequested`, `FiltersChanged`…).
2. Представитель работает с окнами только через интерфейсы (`ILoginView`, `ICatalogView`…), поэтому его можно
   проверить без экрана — подставив «фальшивый» вид.
3. Модель ничего не знает ни об окнах, ни о представителях. Об изменениях она сообщает событием `Changed`,
   а представители перерисовывают свои страницы (например, при смене валюты или добавлении в корзину).

### Пример 1. Вход — те же 7 шагов, что в методичке

1. **Вид** `LoginView` показывает форму.
2. **Пользователь** вводит email и пароль, нажимает «Войти».
3. **Вид** перехватывает нажатие (`LoginButton_Click`) и передаёт его событием `LoginRequested`.
4. **Представитель** `LoginPresenter` обрабатывает данные (обрезает пробелы у email, проверяет формат)
   и передаёт их модели: `model.Login(email, password)`.
5. **Модель** `AuthModel` ищет пользователя и обновляется: `CurrentUser`, `Message`.
6. **Представитель** берёт результат: ошибку передаёт виду (`view.ShowError(model.Message)`),
   а при успехе сообщает приложению, что можно открыть магазин.
7. **Вид** показывает ошибку, или приложение открывает главное окно.

### Пример 2. «В корзину» на странице товара

1. `ProductView` передаёт нажатие событием `AddToCartRequested`.
2. `ProductPresenter` проверяет, что выбран размер (иначе — «Выберите размер.»), и вызывает `CartModel.Add(...)`.
3. `CartModel` применяет правила сайта: ресейл — один экземпляр, не больше 10 штук, размер есть у товара.
4. Модель сообщает `Changed` → `ShellPresenter` обновляет счётчик в шапке, а представитель страницы показывает сообщение.

### Пример 3. Оформление заказа

`CheckoutPresenter` ведёт пользователя по 4 шагам и на каждом проверяет формат полей (телефон, email, номер карты
по алгоритму Луна, срок действия, CVC). Деловые правила проверяет `OrderModel.PlaceOrder`: корзина не пуста,
наличными можно платить только курьеру, для курьера нужен адрес, для самовывоза — пункт выдачи.
Оплата картой сразу подтверждает заказ, ЕРИП оставляет его в статусе «Оформлен» до оплаты.

## Откуда данные

`Data/amfibia.json` выгружен из репозитория сайта по правилам `db/seed.js`: те же 714 товаров и цены
(включая расчётную цену `fallbackPrice`), описания, состав и уход (`texts.js`), размерные сетки (`sizes.js`),
бренды с хронологией из полных историй (`db/content/histories`), тестовые пользователи, способы доставки и оплаты,
промокоды, курсы валют и статусы заказов (`ru.json`). Демо-заказы и отзывы построены по тем же правилам, что
в `seed.js` (отзывы только на доставленные вещи), с фиксированным генератором случайных чисел.

Фотографии товаров в программу не включены: по README сайта они принадлежат правообладателям.
Вместо них, как в заглушках сайта (`scripts/placeholder-art.js`), рисуется силуэт вещи её цветом на фоне
в палитре модного дома.
